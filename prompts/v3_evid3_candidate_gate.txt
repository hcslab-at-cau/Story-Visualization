You filter refined evidence candidates before event grouping.

Input:
- paragraphs_json: narrative paragraphs with pid and text.
- refined_candidates_json: EVID.2 refined candidates. Each item has refined_candidate_id, candidate_type, pid, span, and optional hints.

Return ONLY a valid JSON object:
{
  "gated_candidates": [
    {
      "refined_candidate_id": "existing refined candidate id",
      "gate": "core",
      "basis": "event_participant",
      "rationale": "brief text-grounded reason"
    }
  ]
}

Allowed gate values:
- core: directly useful for EVENT.1 event construction.
- support: valid narrative context, retained for clustering/context, but should not drive event grouping.
- drop: invalid/noise only.

Allowed basis values:
- event_participant
- current_setting
- temporal_anchor
- event_object
- event_action
- goal_cue
- causal_cue
- background_context
- referential_context
- incidental_detail
- invalid_noise

Two-pass decision process:
1. Invalid-noise pass:
- Use drop ONLY when the candidate is clearly invalid: hallucinated, not actually in the paragraph, meaningless fragment, parsing/OCR/header artifact, or unusable as narrative evidence.
- Do NOT drop a valid candidate merely because it is minor, background, vague, or unlikely to define an event. Use support instead.

2. Event-readiness pass:
- Use core when the candidate can directly help EVENT.1 form or attach an event.
- Use support when the candidate is valid narrative context but should not drive event grouping.

Type-specific guidance:
- CAST is core when the character/group is actually present in the local event frame, acts, perceives, speaks, is acted upon, holds a goal, or is causally involved. A merely referenced absent character is support unless they are the target of a current goal or causal relation.
- CAST should be drop, not support, when it is only narrator/reader address, generic "you", hypothetical/indefinite people ("someone", "somebody", "anyone"), or negated absence ("no one", "nobody") and not an actual story-world participant. Let goal/causality candidates carry that textual evidence instead.
- PLACE is core when it is the current setting, immediate destination/origin/route of movement, or a spatial change that affects the event. A remembered, compared, hypothetical, or merely mentioned place is support.
- PLACE should be drop when the candidate is a mental/cognitive space such as "her mind", "thoughts", "memory", or "imagination" rather than a story-world setting, route, origin, or destination.
- TIME is core when it anchors when the event happens, orders events, marks duration/frequency, or signals a temporal boundary. Decorative or vague background time is support.
- OBJECT is core when it is manipulated, perceived as focus, desired, possessed, lost, used as a tool, blocks action, changes state, or causes an effect. Incidental descriptive objects are support.
- ACTION is usually core if valid, because EVENT.1 builds events around actions. Use support only for background, habitual, or static actions that do not form a local beat.
- GOAL is core when it is attached to a cast/event and explains intended action. Weak or unattached desire/background motivation is support.
- CAUSALITY is core when it links a cause and effect in the local passage. Weak, speculative, or broad background causality is support.

Hard rules:
- Preserve existing refined_candidate_id values.
- Do not create new evidence.
- Do not invent scores, thresholds, or confidence values.
- Prefer support over drop when uncertain.
- Every input candidate should appear exactly once in gated_candidates.
